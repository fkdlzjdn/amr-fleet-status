# AMR Fleet Status

**ROS1/ROS2 로봇 현황 모니터 및 DO 점검 도구**입니다. 현황은 읽기로 수집하며, IO 체크의 DO 버튼은 사용자가 누를 때 기존 드라이버 서비스로 출력 변경을 요청합니다.

## 현재 구현

- `192.168.20.51–100` / `R_001–R_050`의 실제 상태를 수집합니다.
- SSH 접속, 실제 ROS 계열/배포판/프로세스, scorpion 상태, bringup, RID, 모델을 확인합니다.
- 로봇별 배터리 잔량(%)·충전 상태를 목록에 표시하고, 상세에서 전압·전류·배터리 토픽·확인 시각을 확인합니다. CSV에도 포함합니다.
- 목록이나 상세의 **IO 체크**에서 `io_driver_node`의 DI·DO 채널을 읽고 ON/OFF·논리 이름·장치·채널 번호·유효 여부를 확인합니다.
- 목록에는 현재 정보 조회에 성공한 로봇만 표로 표시합니다. 카드/전체 보기와 접속 실패·조회 대기 행은 제거했습니다.
- 수집 설정에서 시작·끝 IP를 저장하면 즉시 범위를 적용합니다. 기본값은 `192.168.20.51–100`이며 서버 재시작 후에도 유지됩니다.
- 응답 없음, 인증 실패, 호스트키 미등록/불일치, 부분 조회 실패를 구분합니다.
- 마지막 확인값과 현재 미확인을 구분하고 상태 변화 이력을 서버에 보관합니다.
- 로봇에 프로그램/에이전트/rosbridge를 설치하지 않습니다. DO 수동 ON/OFF를 지원하며, 주행·파라미터·시작 설정 변경 기능은 제공하지 않습니다.

## 빠른 시작

### 준비 사항

- 실행 PC/서버: Node.js 20 이상, npm, Git. 로봇과 SSH 통신이 가능한 네트워크.
- 조회 대상: Linux 로봇, Python 3, SSH 접속 권한. 기본 프로세스 조회에는 별도 ROS 패키지 설치가 필요하지 않습니다.
- ROS2 배터리 실시간 수신: 로봇의 기존 `rclpy`, `sensor_msgs` 및 BatteryState publisher.
- IO 조회/DO 제어: ROS2 `io_driver_node` 및 기존 `spx_io_msgs` 인터페이스. 다른 IO 드라이버는 자동 호환되지 않습니다.
- 테스트 실행에는 실행 PC에도 Python 3가 필요합니다.

```bash
git clone https://github.com/fkdlzjdn/amr-fleet-status.git
cd amr-fleet-status
npm ci
cp .env.example .env
chmod 600 .env
```

`.env`의 `FLEET_SSH_USER`를 로봇 계정에 맞게 수정합니다. 기본 키는 `~/.ssh/id_rsa`, 호스트키 파일은 `~/.ssh/known_hosts`이며, 다른 파일을 쓰면 `FLEET_SSH_KEY`와 `FLEET_KNOWN_HOSTS`에 **절대 경로**를 지정합니다. `.env` 값의 `~`는 자동 확장하지 않습니다. 암호화된 키는 `FLEET_SSH_KEY_PASSPHRASE`를 설정합니다.

대상 로봇의 SSH 호스트키는 지문을 확인해 `known_hosts`에 등록되어 있어야 합니다. 예를 들어 직접 `ssh -p 22 <로봇계정>@<로봇IP>`로 접속하고 장비의 지문을 확인합니다. `.env`와 SSH 키는 사용자마다 별도로 준비하며 저장소에 포함하지 않습니다.

```bash
npm start
```

브라우저에서 **http://127.0.0.1:3100**을 엽니다. 같은 LAN의 다른 PC는 `http://<실행 서버 IP>:3100`에 접속합니다. 서버는 전체 인터페이스에서 수신하며 실행 터미널을 켜 둡니다.

기본 조회 범위는 예제 `192.168.20.51–100`입니다. **수집 설정 → 시작 IP/끝 IP → 저장**으로 자신의 로봇 LAN에 맞게 변경합니다. 사설 IPv4 최대 256개를 지원합니다. 예제 IP와 RID는 기본값이며 실제 배포 정보가 아닙니다. 새로 받은 환경에는 기존 조회 이력이 없으므로 첫 조회가 끝날 때까지 기다립니다.

포트별 설정을 바꾸려면 아래와 같이 로컬 설정을 만들고 `ssh_port`, `ssh_port_fallbacks`를 수정합니다. 기본 50개 항목의 RID/IP 구조는 유지하며, 다른 서브넷은 UI에서 지정합니다.

```bash
cp config/fleet.inventory.example.json config/fleet.json
```

`config/fleet.json`, `.env`, `runtime/`는 Git에서 제외합니다. 별도 빌드 없이 `npm start`로 실행합니다. UI가 열려도 SSH 키 또는 호스트키가 맞지 않으면 로봇 데이터는 조회되지 않습니다. 목록에는 현재 조회 성공 로봇만 표시하며, 실패 원인은 요약과 변경 이력에서 확인할 수 있습니다.

### 같은 LAN에서 사용

서버 IP의 TCP 3100에 접근할 수 있어야 합니다. 여러 브라우저는 같은 서버의 수집·실시간 구독을 공유합니다. 현황·IO 조회는 누구나 사용할 수 있으며 DO 제어는 기본 비활성화입니다. 관리자가 서버에 PIN을 설정하고 활성화한 경우에만 IO 화면에서 PIN 인증 후 제어할 수 있습니다. 조회 범위 변경에는 별도 PIN을 요구하지 않습니다. Public GitHub 저장소는 소스 공개이며 로봇 대시보드를 인터넷에 공개하는 설정은 아닙니다.

### 백그라운드 실행 (Linux/systemd)

`deploy/amr-fleet-status.service`는 사용자 서비스 예제입니다. `/usr/bin/node`가 설치된 Linux에서 프로젝트 루트를 가리키는 링크를 준비합니다.

```bash
mkdir -p ~/deployed ~/.config/systemd/user
ln -s "$PWD" ~/deployed/amr-fleet-status
cp deploy/amr-fleet-status.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now amr-fleet-status
systemctl --user status amr-fleet-status
```

링크가 이미 존재하면 현재 대상을 확인해 사용합니다. Node.js 경로가 다르면 서비스의 `ExecStart`를 수정합니다. 로그아웃 후에도 유지하려면 서버 정책에 따라 `loginctl enable-linger "$USER"`를 설정합니다. 설정 변경 후 `systemctl --user restart amr-fleet-status`로 재시작합니다.

### 문제 확인

| 증상 | 확인 항목 |
|---|---|
| UI 접속 실패 | 실행 로그의 실제 URL, 포트 충돌, 서버/LAN 방화벽 |
| 목록에 로봇 없음 | 대상 IP 범위, 첫 조회 진행률, 서버→로봇 SSH 접속 권한 |
| 키 미등록 / 키 불일치 | 대상 장비의 실제 지문과 `FLEET_KNOWN_HOSTS` 파일 |
| 인증 실패 | 접속 계정, 키 경로/암호 또는 비밀번호 |
| 배터리 미확인 | BatteryState publisher, 실행 ROS 환경, 수신 지연 표시 |
| IO 비활성화 | `io_driver_node` 실행 여부와 지원 ROS2 메시지/서비스 |

포트 충돌 시 `.env`의 `PORT`를 변경합니다. WSL에서 Windows 브라우저로 접속할 때는 `http://127.0.0.1:3100`을 우선 사용합니다.

## 인증 및 대상 설정

기본 접속 계정은 `syscon`, 개인 키는 서버 계정의 `~/.ssh/id_rsa`, 신뢰 호스트키는 `~/.ssh/known_hosts`입니다. 기존 known_hosts 키와 일치하지 않으면 접속을 중단하고 화면에 원인을 표시합니다. 새 키를 자동 신뢰하거나 기존 키를 덮어쓰지 않습니다.

필요하면 `.env.example`을 `.env`로 복사해 서버에서 접속 계정·키 경로·비밀번호를 설정합니다. 비밀번호/키/키 암호는 API나 브라우저로 반환하지 않습니다. `.env`와 `runtime/`는 버전 관리에서 제외합니다. 환경 설정 변경은 서버 재시작 후 반영됩니다.

- `FLEET_SSH_USER`: 접속 계정.
- `FLEET_SSH_KEY`: 개인 키의 절대 경로.
- `FLEET_SSH_PASSWORD`: 필요한 경우 password 인증. 키를 먼저 시도합니다.
- `FLEET_SSH_KEY_PASSPHRASE`: 암호화된 개인 키의 암호.
- `FLEET_KNOWN_HOSTS`: known_hosts 경로.
- `FLEET_INTERVAL_MS`: 재조회 목표 간격. 기본 30000, 최소 15000.
- `FLEET_CONCURRENCY`: 동시 조회 최대 수. 기본 5, 최대 10.
- `PORT`: UI 서버 포트, 기본 3100.
- `DO_CONTROL_ENABLED`: `true`일 때만 DO 제어 허용. 기본 비활성화이며 유효한 PIN도 필요합니다.
- `DO_CONTROL_PIN`: 관리자가 서버 `.env`에 설정하는 6~12자리 숫자. 미설정/형식 오류이면 제어를 비활성화합니다. 공용 기본 PIN은 없습니다.

로봇별 포트는 로컬 `config/fleet.json`에서 설정합니다. 파일이 없으면 `config/fleet.inventory.example.json`을 사용합니다. 기본 22 후 2222, .75는 2222 우선입니다. 실패한 인증을 다른 포트로 반복하지 않습니다. 수집 설정에서 사설 IPv4의 시작·끝 범위를 지정합니다. 최대 256개이며 역순·잘못된 IP는 저장하지 않습니다. `runtime/scan-range.json`에 저장합니다. 기본 범위의 기존 포트 설정은 유지하고 그 밖의 IP는 22 → 2222를 사용합니다. 기본 등록 범위 밖에서는 RID를 IP로 추정하지 않고 실제 관측 RID를 표시합니다. HTTP 요청으로 원격 명령을 지정할 수 없습니다.

## 수집 동작

SSH 연결마다 고정된 Python3 읽기 스크립트를 메모리에서 실행합니다. Python3가 없는 장비는 조회 실패로 표시하고 자동 설치하지 않습니다. 기본 프로세스·서비스 조회와 ROS1 배터리 읽기는 ROS 라이브러리가 필요하지 않습니다. ROS2 배터리 읽기는 로봇에 이미 있는 `rclpy`와 `sensor_msgs`를 사용합니다.

프로세스·서비스 조회는 `systemctl show scorpion.service`, `/proc`, `/etc/os-release`, `/opt/ros` 목록과 한정된 시작 설정 파일을 읽습니다. 배터리는 기존 ROS 토픽을 구독합니다. `.bashrc`/시작 스크립트를 실행하거나 제어 publisher/goal/parameter write를 호출하지 않습니다. shell 환경 파일 전체나 사용자 비밀은 반환하지 않습니다.

### 배터리 수집

충전 상태는 잔량 위의 **제어 버튼**으로 구분합니다. 버튼을 누르면 충전 전용 패널이 열립니다. **충전 중**은 초록색 채움·번개 아이콘, **충전 안 함**은 회색 테두리·플러그 해제 아이콘, **충전 완료**는 파란색, **충전 미확인**은 노란색입니다. 전류로 판정한 경우 전류값과 방전 여부를 함께 표시하며, 상세·CSV의 판정 정보는 유지합니다.

- 실행 중인 ROS 프로세스의 ROS 환경과 namespace/RID를 확인해 `sensor_msgs/BatteryState` 또는 `sensor_msgs/msg/BatteryState` 타입의 `*/battery_state` 토픽을 읽습니다. `/R_011/battery_state`, `/R_001/bms_node/battery_state` 등을 지원합니다. 다른 RID의 토픽을 대신 선택하지 않습니다.
- ROS1은 master의 조회 API와 TCPROS로 한 메시지를 읽습니다. ROS2는 기존 Python 환경에서 임시 구독 노드를 실행하며 `BEST_EFFORT`/`VOLATILE` QoS를 사용합니다. 로봇의 시작 설정 변경·설치·배터리 장치 직접 연결은 하지 않습니다.
- 단건 배터리 읽기는 최대 4.5초 후 자식 프로세스를 종료하고 정리합니다. 배터리 수신 실패가 기존 모델·ROS·서비스 조회 성공을 무효화하지 않습니다.
- `percentage`의 0~1 값을 0~100%로 변환합니다. 0%는 유효한 값입니다. 토픽 미발행, 여러 후보·publisher, ROS 읽기 환경 미확인, 범위 오류, 배터리 미연결, 90초를 넘긴 메시지는 잔량을 **미확인**으로 표시합니다. 전압으로 잔량을 추정하지 않습니다.
- 상세의 조회 결과에서 미확인 이유를 확인할 수 있습니다. 재시작·조회 실패·오래된 정보의 배터리는 이전 확인값으로만 남깁니다. 배터리 잔량 20% 이하는 주황색으로 표시합니다.
- 목록의 잔량 위에 충전 상태를 항상 표시합니다: **충전 중 / 충전 안 함 · 방전 중 / 충전 안 함 / 충전 완료 / 충전 상태 미확인**. 실행 중인 SLEC 플러그인과 해당 배터리 발행 노드의 일치가 확인되면 전류를 사용합니다: +0.1A 초과 충전, -0.1A 미만 방전, 그 사이 충전 전류 없음. 0.1A는 UI 표시용 데드밴드입니다. 부호 규약이 확인되지 않은 BMS는 기존 `power_supply_status`를 사용합니다. 잔량만 유효하지 않아도 신선한 메시지의 충전 상태는 별도로 표시합니다. 상세·CSV에도 같은 문구를 사용합니다. 상세에서는 판정 근거·BMS 원래 상태·IO 충전 신호를 분리해 표시합니다. IO 릴레이 신호만으로 실제 충전 전류가 흐른다고 판정하지 않으며, 충돌하면 충전 정보 불일치로 표시합니다.

### 배터리·충전 상태 실시간 반영

ROS2에서 정상 조회된 로봇은 대시보드를 보는 동안 SSH 연결과 BatteryState 구독을 유지합니다. 배터리 잔량·전류·충전 배지는 **최대 5Hz(약 0.2초 간격)**로 별도 SSE 이벤트를 통해 갱신하며, 기본 현황의 30초 재조회를 기다리지 않습니다. 로봇의 실제 배터리 발행 주기가 더 느리면 그 주기를 따릅니다.

- 목록과 상세에 **실시간 수신 / 연결 중 / 갱신 정지 / 수신 지연**을 구분합니다. 배터리 이벤트는 해당 셀만 갱신하고, 일반 현황의 전체 갱신에도 최신 배터리 값을 유지합니다.
- 같은 로봇을 여러 브라우저에서 보면 서버의 구독 하나를 공유합니다. 마지막 화면을 닫거나 모든 화면이 숨겨지면 배터리 구독을 종료합니다. 화면을 다시 열거나 실시간 갱신을 켜면 재연결합니다.
- 새 데이터가 2초 동안 오지 않으면 이전 충전 상태를 미확인으로 바꿉니다. 네트워크 단절 시 재연결을 시도하며 과거의 주기 조회값으로 충전 중 표시를 되돌리지 않습니다. 브라우저의 경과 시간은 로컬 수신 시각으로 계산합니다.
- SLEC 전류 규약은 실제 BMS publisher와 적재 플러그인을 확인한 경우에만 적용합니다. BMS 프로세스가 바뀌면 기존 규약을 무조건 물려주지 않고 연결을 다시 확인합니다.
- 최초 연결에는 SSH·ROS 발견 시간이 필요합니다. ROS1 등 지속 구독 대상이 아닌 항목은 기존 주기 조회로 표시합니다. 로봇 프로그램 설치나 출력 제어 없이 기존 메시지만 읽습니다.

### IO 체크

목록의 **IO 체크** 또는 로봇 상세의 **IO 체크 열기**를 누릅니다. ROS2 `io_driver_node`가 발행하는 `spx_io_msgs/msg/IoStatus`의 `io/status`를 구독합니다. 참고 로봇 r56에서는 `/R_006/io_driver_node` → `/R_006/io/status`, `ezi_io_main` DI 8개·DO 8개를 확인했습니다. 다른 로봇도 같은 노드·메시지를 제공하면 사용할 수 있습니다. ROS1이나 다른 IO 인터페이스는 미지원 사유를 표시합니다.

- 장치별로 묶고 DI 입력·DO 출력 표를 나란히 배치합니다. 채널 번호순으로 정렬하고 논리 이름과 **ON · 1 / OFF · 0 / 미확인**을 같은 행에 표시합니다. DI는 초록색, DO는 파란색 계열로 구분합니다. `is_valid=false`이거나 잘못된 값은 OFF로 간주하지 않으며, 바뀐 행은 잠시 강조합니다.
- 원시 채널값을 표시하므로 반전 설정이 적용된 논리 신호와 다를 수 있습니다. ON/OFF는 안전 상태 또는 물리 장치 동작의 판정이 아닙니다.
- 패널을 연 동안 SSH 연결·ROS 구독을 유지하며 기존 `io/status` 메시지를 최대 20Hz로 전달합니다. 서버에서 브라우저로 SSE(`/api/robots/<ID>/io/events`)를 사용합니다. 행 전체를 재생성하지 않고 바뀐 표시만 갱신합니다. 최초 연결에는 SSH·ROS 발견 시간이 필요하며, 구독 후 주기는 원래 IO 발행 주기와 네트워크 상태에 따라 달라집니다.
- 같은 로봇을 여러 브라우저에서 보면 하나의 IO 구독을 공유합니다. 동시에 서로 다른 로봇은 최대 2개까지 조회합니다. 마지막 패널을 닫거나 탭을 숨기면 스트림을 해제합니다. 로봇의 임시 읽기 프로세스는 SSH stdin 종료 또는 8초간 lease 미수신 시 종료합니다. 기존 30초 현황 수집과 별도로 동작합니다.
- 노드/토픽 부재·중복 publisher·잘못된 값은 미확인으로 표시합니다. 스트림에서 새 메시지를 1초 동안 받지 못하면 채널을 비우며, 브라우저도 메시지 나이와 화면 경과 시간을 합해 2초를 초과하면 미확인으로 바꿉니다. 서버는 스트림 응답이 3초간 없으면 연결을 정리합니다.
- IO 버튼은 기존 현황 수집에서 `io_driver_node` 프로세스 실행이 확인되면 초록색, 미실행이 확인되면 빨간색·비활성화, 미확인이면 회색으로 표시합니다. 열린 스트림에서 수신 성공 또는 프로세스 미실행을 확인하면 버튼에도 반영합니다. 기본 버튼 상태 확인 주기는 기존 현황 수집과 같습니다.
- 단건 읽기 API `GET /api/robots/<등록 ID>/io`도 유지합니다. 스트림이 있으면 현재 값을 공유하고 단건 조회는 1.5초 캐시·동시 요청 합치기를 사용합니다. IO command 직접 발행은 사용하지 않습니다. 상태 구독과 명시적인 DO 요청을 메모리에서 처리하며 로봇 프로그램·설정을 설치·수정하지 않습니다.

ROS 설정/실행, 실제 namespace/RID, 실행 모델을 현재 프로세스에서 먼저 확인합니다. 실행 근거가 없으면 시작 설정의 정적 내용을 보완합니다. 설치된 distro 목록만으로 ROS 실행 중이라고 판정하지 않습니다. 프로세스 기반 상태이며 ROS graph 및 실제 주행 준비를 보증하지 않습니다.

기본 30초 목표로 조회하지만 전체 응답 시간과 제한된 동시성 때문에 큐 대기가 생길 수 있습니다. 실패한 대상은 최대 60초 간격으로 재시도합니다. 실제 갱신 시각·초기 조회 진행률·대기 수를 화면에 표시합니다. 중복 조회는 합치며 느린 로봇이 다른 로봇 결과 표시를 막지 않습니다.

### 충전 ON/OFF

목록 또는 상세의 **충전 중 / 충전 안 함 / 충전 완료 / 충전 미확인 · 제어 ↗** 버튼을 누릅니다. 충전 전용 패널에서 현재 배터리 충전 상태·전류·릴레이 원시값을 확인하고, 기존 DO PIN으로 인증한 뒤 **충전 ON** 또는 **충전 OFF**를 선택합니다. 상태 버튼을 누르는 동작 자체는 출력을 변경하지 않습니다.

- ROS2 IO의 `charge_relay`라는 이름이 유일하고 유효한 DO로 확인될 때 지원합니다. 이름이 없거나 DI/중복/무효/수신 지연이면 제어를 차단하며 다른 채널을 추측해서 선택하지 않습니다.
- 전용 API `POST /api/robots/<ID>/io/charge`는 `requestId`, `value`(0/1), `expectedValue`(현재 원시값)만 받습니다. 서버가 실시간 IO에서 대상 장치·채널을 선택하고 기존 DO 검증·보호 서비스·논리값 readback을 사용합니다. 클라이언트가 임의 논리 이름을 지정할 수 없습니다.
- PIN 인증은 기존 IO 화면과 같은 연결 단위의5분 유효기간·재잠금·실패 제한을 따릅니다. 서버에 PIN을 설정하지 않았거나 제어가 비활성화되어 있으면 조회만 가능합니다.
- ON/OFF는 **충전 릴레이의 논리 출력 요청**입니다. 드라이버의 충전 소유권·인터록 조건에 따라 거부될 수 있으며 우회하거나 자동 재전송하지 않습니다. 릴레이 논리값 확인을 실제 충전 시작/정지로 표시하지 않습니다. 실제 충전 표시는 기존 전류/BMS 수신값으로 계속 갱신합니다.
- 실시간 배터리가 들어올 때도 목록의 버튼 DOM을 유지하여 클릭·키보드 포커스가 끊기지 않도록 처리합니다.

### DO ON/OFF 제어

DO 제어는 기본 비활성화이며 조회는 계속 사용할 수 있습니다. **실행 서버 관리자**가 프로젝트 폴더의 터미널에서 아래 명령을 실행해 직접 정한 6~12자리 숫자를 두 번 입력합니다. 입력 내용과 PIN 값은 화면에 출력하지 않습니다.

```bash
npm run set-pin
```

이 명령은 기존 SSH 설정을 보존하며 `.env`에 `DO_CONTROL_PIN`과 `DO_CONTROL_ENABLED=true`를 저장하고 권한600을 적용합니다. 서버를 재시작하고 브라우저를 새로고침한 뒤, 충전/IO 패널의 **DO 제어 PIN** 칸에서 인증합니다. systemd 실행 시 `systemctl --user restart amr-fleet-status`를 사용합니다. 비활성화하려면 `.env`의 `DO_CONTROL_ENABLED=false`로 변경하고 재시작합니다. `.env`는 Git에 올리지 않습니다. 실행 중 PIN을 설정·조회하는 웹 API는 없습니다. PIN 미설정 상태에서도 입력란과 관리자 설정 방법은 표시하며, 인증·출력 버튼은 잠깁니다.

IO 체크의 **DO 제어 PIN → 잠금 해제**로 인증하고 **DO 출력 → 논리 제어** 열에서 ON/OFF를 누릅니다. DI에는 제어 버튼이 없습니다. 인증은 해당 로봇의 해당 IO 연결에서만 최대5분간 유효하며 다른 사용자 화면에는 공유되지 않습니다. **제어 잠금**, 패널 닫기, 페이지 숨김/재연결, 서버 재시작 시 다시 인증해야 합니다. 실시간 상태를 받은 유효한 DO 채널에서만 버튼을 사용할 수 있습니다. 모터 전원·충전 릴레이 등 실제 연결 장치에 적용되는 요청입니다.

- 실제 PIN은 정적 화면 코드·API 응답·로그·CSV·Git에 포함하지 않습니다. 입력값은 인증 요청 직후 입력창에서 지우며 앱은 브라우저 저장소에 보관하지 않습니다. 서버는 비교용 해시와 유효기간으로 판정합니다. HTTP 요청 본문으로 입력한 PIN을 전송하므로 네트워크 암호화가 필요한 환경에서는 HTTPS를 별도로 구성해야 합니다. 브라우저 개발자 도구나 통신 경로에서 요청 내용을 숨기는 기능은 아닙니다.
- PIN은 IP별1분에5회 실패 후 해당 시간 창에서 추가 인증 시도를 제한하며 전체 실패50회 제한도 적용합니다. 제한 시429와 Retry-After를 반환합니다. 새 IO 연결을 열어도 실패 횟수는 초기화되지 않습니다.

- 기존 `io/set_output` (`spx_io_msgs/srv/SetOutput`)에 논리 이름과 0/1을 전송합니다. r56 배포 소스의 `writeOutputByNameGuarded` 경로를 확인했으며, 보호 조건이나 충전 소유권으로 거부된 요청을 우회하지 않습니다.
- 표의 상태는 **원시값**, 버튼은 **논리값**입니다. 반전 설정에 따라 서로 다를 수 있습니다. 서비스가 성공을 응답한 뒤 새 IO 메시지와 `io/get_input`의 논리값을 확인하여 **논리 ON/OFF 확인**을 표시합니다. 이는 드라이버 논리값 확인이며 외부 계측을 통한 물리 동작 검증은 아닙니다.
- 표시를 먼저 ON/OFF로 바꾸지 않습니다. 수신 상태를 계속 표시하고 결과는 확인·거부/실패·미확인으로 구분합니다. 한 로봇에서 DO 요청을 하나씩 처리하며 결과가 미확인이면 자동 재전송하지 않습니다. 패널 닫기나 연결 종료가 이미 전송된 명령을 취소하지는 않습니다.
- 같은 요청 ID는 서버 프로세스 내에서 5분 동안 결과를 공유하며 재전송하지 않습니다. 활성 IO 연결·현재 채널 이름/장치/번호·유효성·예상 원시값과 2초 이내 최신 상태를 서버와 원격 worker에서 검사합니다.
- 인증 API: `POST /api/robots/<ID>/io/unlock`의 JSON `{pin: ...}` 및 열린 SSE의 `X-IO-Control-Token`. 실제 PIN/해시를 응답하지 않습니다. `POST /api/robots/<ID>/io/lock`으로 해당 연결의 인증을 해제합니다.
- 제어 API: `POST /api/robots/<ID>/io/output`. 같은 Origin, JSON, 열린 SSE 연결의 `X-IO-Control-Token`과 만료되지 않은 PIN 인증이 필요합니다. PIN을 제어 요청마다 재전송하지 않습니다. 현재 등록 범위의 로봇만 요청할 수 있으며 SSE가 닫히면 토큰을 폐기합니다. 서비스 경로·셸 명령을 HTTP 입력으로 받지 않습니다.
- 검증은 모의 ROS 서비스와 격리된 브라우저 테스트 서버로 수행합니다. 실제 로봇 출력은 자동 테스트에서 전환하지 않습니다.

## 저장 및 UI

`runtime/fleet-state.json`에 최신 수집 상태와 로봇별 30일/최대 30개 변화 이력을 원자적으로 저장합니다. 서버 재시작 시 이전 값은 별도 이전 확인값으로만 복원하고, 새 조회 전 현재 정보는 미확인으로 표시합니다. 성공 정보가 90초 이상 갱신되지 않으면 오래된 정보로 표시합니다.

정보 조회 성공 로봇의 표, RID/IP/모델 검색, ROS·모델 필터, 상세 패널, 실제 상태 변화 이력, 현재 표시 목록 CSV, 범위 전체/개별 읽기 새로고침, SSE 화면 갱신 일시 정지를 제공합니다. 현재 조회 실패나 stale 상태는 목록에서 제외합니다. 범위를 바꾸면 이전 범위의 대기 작업을 폐기하고 진행 중 결과는 무시합니다. 진행 중 SSH가 끝날 때까지 슬롯을 점유하므로 동시 조회 제한은 유지됩니다. 브라우저 수가 늘어도 수집 작업이 늘어나지 않습니다.

## WSL2에서 LAN IP 접근

서버는 기본적으로 IPv4·IPv6 전체 인터페이스의 TCP 3100을 수신합니다. WSL2 mirrored 환경에서 같은 Windows PC는 시작 로그의 `http://127.0.0.1:3100`으로 접속합니다. 다른 LAN PC에서의 접속은 Windows 및 WSL 방화벽의 인바운드 허용 여부에 따라 달라집니다.

Windows 탐색기에서 프로젝트의 `scripts/Enable-LanAccess.cmd`를 실행하고 관리자 UAC를 허용하면 **TCP 3100, 원격 192.168.20.0/24만** Windows 및 WSL 방화벽에 허용합니다. 설정은 [Enable-LanAccess.ps1](scripts/Enable-LanAccess.ps1)에서 검토할 수 있습니다. 실행 시 Windows 관리자 권한이 필요합니다. 자신의 서브넷에 맞게 `-RemoteSubnet`을 지정합니다. WSL 재시작/전체 방화벽 해제는 하지 않습니다.

다른 LAN PC에서는 시작 로그에 표시된 현재 서버의 LAN IP로 접속합니다. IP는 네트워크 연결에 따라 바뀌므로 이전 주소를 재사용하지 않습니다. 같은 Windows PC에서는 `http://127.0.0.1:3100`을 사용합니다. 다른 PC에서의 LAN 접근은 해당 PC에서 별도로 확인해야 합니다.

참고: https://learn.microsoft.com/windows/wsl/networking / https://learn.microsoft.com/windows/security/operating-system-security/network-security/windows-firewall/hyper-v-firewall

## 운영 대시보드 UI (2026-10-16)

상단은 슬레이트 색상의 압축된 플릿 모니터링 패널로 표시합니다. 등록/조회 성공/확인 필요 수와 SSH 수집 방식, 설정된 기본 조회 목표 주기, ROS2 실시간 구독 방식을 보여 줍니다. `수집 파이프라인`에서 SSH 조회 → 주기 조회·토픽 구독 → SSE 전달 흐름과 DO 요청 방식을 펼쳐 볼 수 있습니다.
